Windows 原生游戏聚合启动器

GAMEBOX3

Node.js + koffi FFI 直接驱动 Win32 / GDI+ 的原生窗口应用 · 单 EXE 即开即用

1

产品功能介绍

适用场景：本地多目录散装游戏（Steam 之外）的统一收纳、封面美化与一键启动。

核心能力

  • 原生窗口：不依赖浏览器，单 EXE 双击运行，启动即最大化
  • 多目录扫描：支持多个游戏根目录，增量扫描只处理新游戏
  • 自动封面：Steam / Bing / DDG 多源抓取，失败可手动补搜
  • 官方中文名：经 Steam 商店 API 校验，确认同款才采用

运行与进程管控

  • 强制单实例：同时仅一款游戏 + 一个修改器，切换自动结束上一款
  • 修改器看门狗：游戏退出 3 秒后自动关闭提权修改器（仅一次 UAC）
  • 幽灵启动防护：屏蔽注入点击、后台节流与最小化期间的误触发
  • 退出即恢复：游戏退出后窗口自动恢复并最大化

操作与交互

  • 手柄支持：可一键开关，严格前台门控（非激活窗口屏蔽一切手柄操作）
  • 金色标记点：封面右上角标注该游戏带有修改器
  • 重命名：悬停卡片即可改名，手动名不被自动中文名覆盖
  • 安全移除：移除目录带确认弹窗，避免误清整库

网络与部署

  • 代理支持：SOCKS5 / HTTP，配置即时生效，可测试连通性
  • 独立打包：Node SEA 打包为单 EXE，拷贝到任意目录即可用
  • 数据随行：配置、游戏库、封面均落在 EXE 同目录，便于迁移
  • 首次引导：空库时弹出系统目录选择框，零配置上手

编写经验与教训总结

基于一次完整的「浏览器版 → 原生 Win32 重写」开发，沉淀可直接复用的硬规则、分领域陷阱与验证方法论。

五条最该记住的铁律

  • ① koffi 声明 flat API 前，逐一核对 GdiplusFlat.h 的签名与参数顺序。 顺序错 / 单位错往往 返回错误码而非崩溃，静默失败最难查（FillPath 把 path 当 brush 用，全程 ObjectBusy 却"看起来正常"）。
  • ② PER_MONITOR_AWARE_V2 下，GetClientRect / WM_SIZE / 鼠标坐标全是物理像素。 缓冲区绝不二次乘 DPI；用 buf == client 断言守住，否则屏幕只显示全部内容的 57%。
  • ③ 自绘 UI 的父窗口必须带 WS_CLIPCHILDREN(0x02000000)。 否则父窗口 BitBlt 会把原生 EDIT 子控件的像素整块擦掉——表现为"输入框要点一下才显示"。
  • ④ 凡"一次性尝试"（搜封面 / 中文名）必须记录尝试时间戳。 不能用"结果是否为空"判断完成态，否则失败态被永久当成"已完成"、后配代理也补不回图。
  • ⑤ 改配置文件用 Node 写，绝不依赖 PowerShell 的 UTF-8。 Set-Content -Encoding UTF8 在 PS5.1 会带 BOM，破坏 JSON.parse 并回落默认值（库被清空）。

分领域教训

FFI / GDI+ 签名

  • GdipFillPath/DrawPath：brush/pen 在 path 之前（不是之后）
  • GdipDrawImage 只有 (x,y)；缩放必须用 GdipDrawImageRect
  • GdipCreatePen1 / GdipCreateFont 的 unit 必须传 2(UnitPixel)，传 3(Point) 静默不画
  • GdipStringFormatGetGenericDefault 是共享对象，三种对齐会互相污染 → 各自 CreateStringFormat

坐标系 / 裁剪

  • 所有 Path 坐标按 dpiScale 乘；Graphics 坐标系 = 设备像素
  • GDI+ 不支持 WebP / SVG，抓图白名单排除，占位图不落盘
  • 1 逻辑像素的竖线在高 DPI 下会变成"贯穿全屏的细线"——暗色 UI 直接不画分隔线

原生 EDIT 控件

  • 必须 WS_CHILD，否则建成 owned popup 跑到窗口外
  • SetWindowTheme(hwnd,"","") 关主题，暗色画刷才生效
  • 颜色是 COLORREF(0x00BBGGRR)，不是 ARGB；字体×dpiScale + WM_SETFONT
  • 验证用 PrintWindow 而非 BitBlt（BitBlt 抓不到子控件）

进程 / 提权

  • spawn 提权程序 EACCES → 降级 Start-Process -Verb RunAs
  • 强制单实例靠 tasklist/taskkill 镜像名，不只 child.pid（引导器秒退）
  • "退出游戏自动启动别的游戏" = 后台节流漏采样 + 断连重连幽灵 → 前台门控 + 轮询间隔保护 + 来源日志
  • 提权子进程交给看门狗管生命周期，全程只要一次 UAC

网络 / 封面

  • 增量优化别跳过失败态：coverTriedAt + fixCovers 三档覆盖
  • 中文名必须反查英文校验，避免 DLC / 同名小游戏误匹配
  • 代理配置即时生效；长标题要生成查询变体，国区不可见退回 cc=us
  • 弱网候选图要并发探测，串行会拖到 90s+

工程化 / 打包

  • Node SEA：postject sentinelFuse 不带 :0；入口剥 shebang
  • 构建前用 PowerShell Remove-Item 清 dist（回收站 safe-delete 遇几千封面文件会失败）
  • 覆盖写 JSON 可能 EPERM（杀软扫描 tmp）→ saveJson 加回退直写
  • PE Subsystem 3→2 去黑窗；原生二进制别漏收集

验证方法论（让问题可定位、可复现）

  1. 渲染层与应用层分离：app 启动后手动渲染一帧即退出，配合 GAMEBOX_DUMP_FRAME 导出 BMP，免重打包即可看图迭代。
  2. BMP→PNG 手搓编码器：用 Node 内置 zlib 转（BGRA→RGB、行序翻转），再用 Read 工具看图。
  3. GDI+ 状态码统计：给每个调用包状态检查，统计 0=Ok / 2=InvalidParameter / 4=ObjectBusy，大量 4 即签名/顺序错。
  4. 来源标记日志：启动/动作入口打 click@x,y / key-Enter / gamepad-A，定位"自己动起来"的元凶。
  5. buf==client 断言：防止"导出图完整、但屏幕只显示一角"的漏判（DPI 双重缩放）。
  6. PrintWindow 验证子控件：PW_RENDERFULLCONTENT 不受遮挡，能真正看到 EDIT 像素。
元经验：一开始就把「帧导出 + 状态码统计 + 来源日志」三件套建好，能省下约 80% 的调试时间——多数 GDI+ 与"幽灵启动"问题靠它们才定位得出来。

给后续原生窗口项目的建议

  • 把 koffi 声明集中管理，并对照 GdiplusFlat.h 逐条校对，别边写边猜——这是本项目耗时最多的隐性成本。
  • 凡是"尝试型"状态机（搜图、取名、下载），先设计时间戳字段，别用结果反推"是否完成"。
  • 自绘 UI 从第一行就加 WS_CLIPCHILDREN 和 buf==client 断言，比事后排查省事得多。
  • 危险动作（启动程序、结束进程）的输入源统一走 门控 + 来源日志，把"后台自己动"变成可观测事件。
  • 配置一律 Node 读写，把"无 BOM"当成写入契约的一部分。
